# Retail Behavioral Analytics Pipeline

A computer vision & behavioral analytics pipeline for retail surveillance cameras, processing multi-camera footage (`entrance.mp4` and `interior.mp4`) to quantify pedestrian traffic, store interest, entrance conversion, shelf engagement, group dwell episodes, and staff-customer interactions.

---

## 1. Overview & Architecture

The pipeline uses a **two-pass offline architecture** designed for high precision in retail environments:

```
Video Stream (.mp4)
       │
[Pass 1: Perception Pass]
 ├─ YOLO11m-Pose Keypoint Estimation (17 COCO keypoints @ 1280x720 / 960x540)
 ├─ BoT-SORT Object Tracking with deep ReID appearance features (yolo26n-reid)
 └─ Streaming Flat Parquet Observation Cache + Embeddings NPY Store
       │
[Pass 2: Assembly & Behavioral Logic]
 ├─ Offline Hungarian Bipartite Stitching (re-identifies broken tracklets across occlusions)
 ├─ Gap Interpolation (<=10 frames) & Savitzky-Golay / Median Signal Smoothing
 ├─ Physical Scale Mapping (pixel distance -> body-height units)
 ├─ Task 3: Staff Classification (Counter zone dwell + dwell prior + apron color)
 ├─ Task 1: Store Interest & Conversion (Orientation, Deceleration, Approach, Dwell)
 ├─ Task 2: Per-Shelf Interest Events (Proximity to annotation rect + Facing + Hysteresis)
 └─ Task 3: Staff-Customer Interaction Episodes
       │
Outputs & Visualizations
 ├─ CSV Reports (Task 1, Task 2, Task 3, Audits)
 ├─ Sensitivity & Ablation Analysis Tables
 └─ Annotated Video Overlays (HUD, zones, engagement progress, session links)
```

# 2. Install dependencies

## 4. Data & Model Provisioning

Several paths are **intentionally excluded from git** (see [`.gitignore`](.gitignore)) because
they are either large binary assets, per-machine artifacts, or scratch caches regenerated by
running the pipeline. A fresh checkout will not have them — here is what each one is and how it
gets populated:

| Gitignored path | What it is | How it's obtained |
| :--- | :--- | :--- |
| `data/videos/*.mp4` | Raw source footage (`entrance.mp4`, `interior.mp4`) | **Not downloadable.** Copy the assignment-supplied files into `data/videos/` manually before running anything. |
| `models/*.pt` | YOLO11m-Pose weights (`yolo11m-pose.pt`) | `bash models/download_models.sh` — fetches it via `ultralytics`' asset downloader. The script is idempotent; it skips files already present. |
| `outputs/*.mp4` | Rendered annotated overlay videos | Produced by `render-entrance-video` / `render-interior-video` (or `--render`). Never hand-authored, so they're not committed — also available pre-built via the Drive mirror below. |
| `outputs/debug/{scene}_observations.parquet`, `outputs/debug/{scene}_embeddings.npy` | Pass-1 perception cache (§5.1) — up to ~41 MB per file | Regenerate with a full `--recache` run (§5.1), or grab the pre-built pair from the Drive mirror below to skip Pass 1 entirely. |
| `__pycache__/`, `.pytest_cache/`, `.venv/`, `.DS_Store`, `.idea/`, `.vscode/` | Standard interpreter/tooling/editor clutter | Regenerated automatically by Python, pytest, your venv manager, and your editor. |

Notes:
- `models/yolo26n-reid.onnx` (the BoT-SORT ReID network referenced by
  `configs/botsort_*.yaml`) is small enough (~10 MB) that it **is committed to the repo**, unlike
  the pose weights — but `models/download_models.sh` will also fetch it if it's ever missing, so
  the script alone is always sufficient to provision `models/`.
- The `Dockerfile` does `COPY . .` and does **not** run `download_models.sh` or fetch videos
  itself — it assumes `models/` and `data/videos/` are already populated on the host before
  `docker build` runs. Run the two steps above first, then build the image.

### Drive Mirror (pre-built annotated videos + Pass-1 cache)

The rendered annotated videos (`entrance_annotated.mp4`, `interior_annotated.mp4`) and the full
Pass-1 cache for both scenes (`entrance_observations.parquet` / `entrance_embeddings.npy`,
`interior_observations.parquet` / `interior_embeddings.npy`) are too large to commit to git and
are mirrored here instead:

**[Google Drive folder](https://drive.google.com/drive/folders/1cP3P2UX7IA7HknzgjW2NZWBvlkXK_Xyu?usp=sharing)**

To use the cache pair, drop both files for a scene into `outputs/debug/` with their original
names, then run `run-entrance` / `run-interior` **without** `--recache` — Pass 1 is skipped and
Pass 2 (stitching, tasks, CSVs) runs against them directly (§5.1). This is a convenience mirror
for reviewers who want the outputs without re-running the ~GPU/MPS-heavy perception pass; treat
a fresh `--recache` run as the source of truth if you're reproducing or auditing results.

## 5. Pipeline Execution Commands

All workflows are controlled via the Typer CLI in `src/cli.py`:

```bash
# Run complete Entrance Pipeline (Task 1 Store Interest + Task 3 Staff & Interactions)
python -m src.cli run-entrance

# Run complete Interior Pipeline (Task 2 Group Dwell & Shelf Engagement)
python -m src.cli run-interior

# Run both scenes end-to-end
python -m src.cli run-all

# Smoke test on a short 30-second window (fast verification only, never for final numbers)
python -m src.cli run-entrance --stride 5 --limit-s 30
python -m src.cli run-interior --stride 5 --limit-s 30

# Render annotated video overlays with HUD
python -m src.cli render-entrance-video
python -m src.cli render-interior-video
```

### 5.1 Recommended Workflow: Full-Fidelity Cache, Then Iterate

The two-pass architecture (§1, §2 of `docs/DESIGN_WRITELOG.md`) means **almost everything you
do after the first real run is free** — but only if that first run built a complete, correct
cache. This is the operating discipline:

#### Step 1 — One full-fidelity perception run per scene, with `--recache`

```bash
python -m src.cli run-entrance --recache
python -m src.cli run-interior --recache
```

Every flag here matters, and the defaults are deliberately the "always do this" setting:
- **Start at frame 0:** there is no `--start` flag — `frame_idx` always begins at `0` inside the
  capture loop in `run_entrance`/`run_interior` (`src/cli.py`). Every run reads the video from
  the beginning; there is no partial/resumed capture.
- **`stride=1` (the default — no need to pass it):** every single frame is sent through
  YOLO11m-Pose + BoT-SORT. Anything higher (`--stride 5`, used by the smoke test) skips frames
  and produces a *sparser* cache — fine for wiring checks, wrong for real numbers, because
  gap-interpolation, median smoothing, and dwell/duration thresholds (§5, §7 of the write-log)
  all assume near-continuous per-frame observations.
- **`limit_s=None` (the default — omit `--limit-s`):** processes the entire video, not a
  truncated window. A capped cache silently produces a capped video and undercounted CSVs later
  — nothing warns you, because §5.2 below explains everything downstream just trusts the cache.
- **`--recache`:** forces Pass 1 to run again and **overwrite**
  `outputs/debug/{scene}_observations.parquet` / `_embeddings.npy`, even if a cache already
  exists. Without it, `run_entrance`/`run_interior` silently reuse whatever is already on disk
  (see the `if recache or not (...).exists()` check in `src/cli.py`) — which is exactly the
  trap: if your only existing cache is the `--stride 5 --limit-s 30` smoke test, every command
  below will keep operating on that same 30-second, every-5th-frame data until you pass
  `--recache` again with the full-fidelity settings.

What this step produces (§12.1 of the write-log has the full schema):
- `outputs/debug/{scene}_observations.parquet` — one row per tracked person per processed frame
  (bbox, 17 pose keypoints + confidences, raw BoT-SORT track id, embedding row reference).
- `outputs/debug/{scene}_embeddings.npy` — the aligned `(N, 512)` L2-normalized ReID vectors.
- The task CSVs (`outputs/task1_*.csv`, `task2_*.csv`, `task3_*.csv`) computed from Pass 2
  (Hungarian stitching → smoothing → behavioral formulas → hysteresis episodes) run
  automatically against that same cache, so they land at full fidelity in the same command.

#### Step 2 — Render the annotated videos from that cache

```bash
python -m src.cli render-entrance-video
python -m src.cli render-interior-video
```

These are **separate commands on purpose**, decoupled from Step 1 (you can also pass `--render`
to `run-entrance`/`run-interior` to trigger them automatically at the end, but calling them
standalone is the normal iteration loop). Crucially:
- `render-*-video` takes **no `--stride` / `--recache`** — it always reads whatever is currently
  cached at `outputs/debug/{scene}_observations.parquet`. It re-runs stitching and the Task 1/2/3
  logic in memory (sub-second — that's the whole point of the cache), then walks the *raw* source
  video frame-by-frame drawing the HUD/zones/overlays, writing `outputs/{scene}_annotated.mp4`.
- Because it inherits the cache's fidelity, **rendering is only as complete as Step 1 was.** If
  Step 1 was run with `--limit-s 30`, the render command still opens the full source video but
  will only have identities/events to draw for the first 30 seconds — the rest of the video plays
  with no overlays. Always confirm Step 1 was a `--recache` run with no `--stride`/`--limit-s`
  before rendering anything you intend to report or submit.
- Re-rendering after only changing `render.py` (HUD colors, text, layout) is cheap and doesn't
  touch Pass 1 at all — just re-run the two commands above.

#### Iterating afterward (config/threshold tuning, the common case)

Once the full cache from Step 1 exists, **do not pass `--recache` again** unless you changed the
video file, the detector/tracker config, or the models. Re-running without it:

```bash
python -m src.cli run-entrance   # no --recache: reuses the cached parquet/npy, Pass 2 only
python -m src.cli run-interior
```

skips Pass 1 entirely (`"Using cached ... observations from ..."` is printed) and re-executes
only Hungarian stitching, smoothing, and the behavioral-formula/hysteresis logic — sub-second
across the full 15k-/20k-row cache (§2 of the write-log). This is how you tune
`configs/entrance.yaml` / `configs/interior.yaml` thresholds (e.g. `interest_threshold`,
`reach_dist_bh`) and get fresh CSVs back almost instantly. If you also want the annotated video
to reflect the new thresholds, re-run the Step 2 render commands afterward — they recompute
Task 1/2/3 from the identities each time, they don't read the CSVs.

**Rule of thumb:** `--stride 5 --limit-s 30` is a wiring smoke test only. Before generating any
CSV or video you intend to report, make sure the cache backing it came from a plain `--recache`
run with no `--stride`/`--limit-s` overrides.

## 6. Methodology & Formulas

### 4.1 Coordinate Normalization via Scale Map
All velocities, distances, and thresholds are normalized by local body height $BH(y) = a \cdot y + b$, making spatial metrics scale-invariant across perspective depth:
- Entrance Camera: $BH(y) = 0.136 \cdot y + 62.0$ px
- Interior Camera: $BH(y) = 0.200 \cdot y + 60.0$ px

### 4.2 Tracklet Stitching
Tracker fragmentation caused by visual occluders (podium, easels, pillars) is repaired using global Hungarian assignment across temporal gaps $\Delta t \le 2.0\text{s}$ with fused cost:
$$C(i, j) = 0.55 \cdot D_{\text{cosine}}(e_i, e_j) + 0.30 \cdot \frac{\|\hat{x}_j - x_j\|}{BH} + 0.15 \cdot \frac{|h_i - h_j|}{h_i}$$

### 4.3 Task 1: Store Interest Formula
Interest $I(t)$ is computed from 4 behavioral channels:
$$I(t) = 0.40 \cdot A(t) + 0.25 \cdot S(t) + 0.20 \cdot P(t) + 0.15 \cdot D(t)$$
- **$A(t)$ (Orientation):** Facing angle towards store entrance line blended with head yaw asymmetry.
- **$S(t)$ (Deceleration):** Speed reduction relative to cruising velocity $v_{\text{cruise}}$ ($80^{\text{th}}$ percentile).
- **$P(t)$ (Approach):** Distance decrease towards entrance line in body heights.
- **$D(t)$ (Storefront Dwell):** Continuous duration spent inside the storefront zone ($>3\text{s} \rightarrow 1.0$).
- **Interest Criterion:** $I(t) \ge 0.55$ sustained for $\ge 0.8\text{s}$.
- **Entered Criterion:** Latched crossing past entrance line with depth $\ge 1.0 BH$ and dwell $\ge 2.0\text{s}$ inside store.

### 4.4 Task 2: Per-Shelf Customer Interest
Shelf rectangles are loaded directly from the ground-truth VIA annotation
(`data/annotations/interior_annotation.csv`); no hand-drawn geometry. Per person and frame,
a shelf candidate requires ALL of:
- **Proximity:** foot-to-rect distance $\le 1.2$ body-heights, normalised by the person's own
  bbox height (perspective-invariant). True browsers measure 0.6–1.2 BH; passers-by $\ge 1.5$ BH.
- **Facing:** torso facing normal within $80^\circ$ of the rect centre — the disambiguator when
  a customer stands between two shelves.
- **Browsing speed:** $v(t) \le 0.35\text{ BH/s}$.
- **Exclusion zones:** the wall mirror (reflection detections) and the cashier counter / staff
  desk (paying != browsing) never generate candidates; both were found during frame-by-frame
  visual verification.

Each frame keeps the nearest candidate, a 1s rolling majority vote removes flicker between
fixtures, and a Hysteresis State Machine ($T_{\text{on}}=2.0\text{s}$, $T_{\text{off}}=3.0\text{s}$)
segments episodes: one continuous interaction = one interest event; a later return = a new event.

### 4.5 Task 3: Staff Detection & Interaction
- **Staff Filter:** Fuses counter zone dwell, long-duration prior, and apron HSV color histogram.
- **Interaction Session:** Concurrent staff-customer pairs within $0.9 BH$, mutually facing ($\le 60^\circ$), co-stationary ($\le 0.35 BH/\text{s}$) for $\ge 2.0\text{s}$.
